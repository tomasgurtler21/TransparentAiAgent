## Request Structure

### Base Endpoint
```
POST https://api.anthropic.com/v1/messages
```

### Complete Request Example
```json
{
  "model": "claude-sonnet-4-5-20250929",
  "messages": [
    {
      "role": "user",
      "content": "Hello, Claude!"
    }
  ],
  "max_tokens": 1024,
  "system": "You are a helpful assistant",
  "temperature": 0.7,
  "top_p": 0.9,
  "top_k": 40,
  "stop_sequences": ["END"],
  "stream": false,
  "tools": [],
  "tool_choice": {"type": "auto"},
  "metadata": {"user_id": "user_123"}
}
```

## Response Structure

### Success Response (HTTP 200)

```json
{
  "id": "msg_013Zva2CMHLNnXjNJJKqJ2EF",
  "type": "message",
  "role": "assistant",
  "content": [
    {
      "type": "text",
      "text": "Hello! How can I help you today?",
      "citations": null
    }
  ],
  "model": "claude-sonnet-4-5-20250929",
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "usage": {
    "input_tokens": 12,
    "output_tokens": 25,
    "cache_creation_input_tokens": 0,
    "cache_read_input_tokens": 0
  }
}
```

### Response Fields

| Field | Type | Always Present | Description |
|-------|------|----------------|-------------|
| `id` | string | Yes | Unique message identifier (format: `msg_*`) |
| `type` | string | Yes | Always `"message"` |
| `role` | string | Yes | Always `"assistant"` |
| `model` | string | Yes | Model that processed the request |
| `content` | array | Yes | Content blocks generated by model |
| `stop_reason` | enum | Yes (non-null in non-stream) | Why generation stopped |
| `stop_sequence` | string | Yes | Matched custom stop sequence or null |
| `usage` | object | Yes | Token usage statistics |

## Parameters Reference

### Required Parameters

#### model (string, required)
- **Description:** Model identifier
- **Constraints:** 1-256 characters
- **Important:** Use versioned IDs in production (e.g., `claude-sonnet-4-5-20250929`), not aliases
- **Examples:**
  - `"claude-sonnet-4-5-20250929"` (Sonnet 4.5 - latest)
  - `"claude-haiku-4-5-20251001"` (Haiku 4.5 - latest)
  - `"claude-opus-4-1-20250805"` (Opus 4.1)

#### messages (array, required)
- **Description:** Conversation turns alternating between user and assistant
- **Constraints:** Max 100,000 messages
- **Important:** First message MUST be role "user"
- **Format:**
```json
[
  {"role": "user", "content": "Hello"},
  {"role": "assistant", "content": "Hi there!"},
  {"role": "user", "content": "How are you?"}
]
```

#### max_tokens (integer, required)
- **Description:** Maximum tokens to generate before stopping
- **Constraints:** Must be ≥ 1
- **Note:** Different models have different maximum values (up to 64K tokens for Sonnet/Haiku 4.5)

### Optional Parameters

#### system (string or array, optional)
- **Description:** System prompt providing context and instructions
- **Default:** null
- **Format 1 - Simple string:**
```json
"system": "You are a helpful assistant"
```
- **Format 2 - Array with cache control:**
```json
"system": [
  {
    "type": "text",
    "text": "Your system instructions here",
    "cache_control": {"type": "ephemeral"}
  }
]
```

#### temperature (number, optional)
- **Description:** Randomness control
- **Range:** 0.0 - 1.0
- **Default:** 1.0
- **Behavior:**
  - 0.0 = Deterministic (most consistent)
  - 1.0 = Creative (most random)
- **Note:** Don't modify both temperature and top_p simultaneously

#### top_p (number, optional)
- **Description:** Nucleus sampling cutoff probability
- **Range:** 0.0 - 1.0
- **Default:** null
- **Note:** Alternative to temperature (don't use both)

#### top_k (integer, optional)
- **Description:** Sample from top K options per token
- **Range:** ≥ 0
- **Default:** null

#### stop_sequences (string[], optional)
- **Description:** Custom text triggers to halt generation
- **Default:** null
- **Example:**
```json
"stop_sequences": ["END", "STOP", "\n\n---"]
```

#### stream (boolean, optional)
- **Description:** Enable server-sent event streaming
- **Default:** false
- **See:** [03_STREAMING_IMPLEMENTATION_GUIDE.md](03_STREAMING_IMPLEMENTATION_GUIDE.md)

#### tools (array, optional)
- **Description:** Tool definitions for function calling
- **Default:** null
- **See:** [02_TOOL_CALLING_DEEP_DIVE.md](02_TOOL_CALLING_DEEP_DIVE.md)

#### tool_choice (object, optional)
- **Description:** Control how model uses tools
- **Default:** `{"type": "auto"}`
- **Options:**
  - `{"type": "auto"}` - Model decides
  - `{"type": "any"}` - Must use at least one tool
  - `{"type": "tool", "name": "tool_name"}` - Force specific tool
  - `{"type": "none"}` - Disable tools

#### metadata (object, optional)
- **Description:** Request metadata with custom key-value pairs
- **Fields:** Includes `user_id` field
- **Example:**
```json
"metadata": {
  "user_id": "user_123",
  "session_id": "session_456"
}
```

## Content Block Types

### Text Block

```json
{
  "type": "text",
  "text": "The actual text content",
  "citations": null
}
```

**Fields:**
- `type`: Always `"text"`
- `text`: The text content
- `citations`: Citation information (usually null)

### Tool Use Block

```json
{
  "type": "tool_use",
  "id": "toolu_01A09q90qw90lq917835lq9",
  "name": "get_weather",
  "input": {"location": "San Francisco, CA"}
}
```

**Fields:**
- `type`: Always `"tool_use"`
- `id`: Unique tool call identifier (format: `toolu_*`)
- `name`: Tool name matching definition
- `input`: Tool parameters as JSON object

**Critical:** When `stop_reason == "tool_use"`, you MUST execute tools and continue the conversation.

### Tool Result Block (in user messages)

```json
{
  "type": "tool_result",
  "tool_use_id": "toolu_01A09q90qw90lq917835lq9",
  "content": "72 degrees Fahrenheit and sunny",
  "is_error": false
}
```

**Fields:**
- `type`: Always `"tool_result"`
- `tool_use_id`: ID from corresponding tool_use block
- `content`: Result data (string or structured)
- `is_error`: Whether execution failed

### Thinking Block (Extended Thinking)

```json
{
  "type": "thinking",
  "thinking": "Let me analyze this problem..."
}
```

**Fields:**
- `type`: Always `"thinking"`
- `thinking`: Model's reasoning process

### Redacted Thinking Block

```json
{
  "type": "redacted_thinking",
  "thinking": "Redacted reasoning..."
}
```

**Note:** Some reasoning may be redacted for various reasons.

## Stop Reasons

| Stop Reason | Description | Action Required |
|-------------|-------------|-----------------|
| `end_turn` | Natural completion | None - response complete |
| `max_tokens` | Hit token limit | Increase max_tokens or handle truncation |
| `stop_sequence` | Custom sequence matched | Check which sequence triggered |
| **`tool_use`** | **Model wants to call tools** | **CRITICAL: Execute tools and continue** |
| `pause_turn` | Long-running turn paused | Handle multi-turn continuation |
| `refusal` | Safety policy triggered | Handle refusal appropriately |
| `model_context_window_exceeded` | Context too large | Reduce conversation history |

**Most Important:** `stop_reason == "tool_use"` means the conversation is NOT complete. You must:
1. Extract tool calls from `content` blocks
2. Execute the tools
3. Send results back in a new user message
4. Continue the conversation

## Error Responses

### HTTP Status Codes

| Status | Error Type | Description |
|--------|------------|-------------|
| 400 | `invalid_request_error` | Issue with request format or content |
| 401 | `authentication_error` | Invalid API key |
| 403 | `permission_error` | API key lacks permission |
| 404 | `not_found_error` | Resource not found |
| 413 | `request_too_large` | Request exceeds size limits |
| 422 | `unprocessable_entity` | Semantic error in request |
| 429 | `rate_limit_error` | Rate limit exceeded |
| 500 | `api_error` | Unexpected internal error |
| 529 | `overloaded_error` | API temporarily overloaded |

### Error Response Format

```json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "Description of the error"
  }
}
```

### Common Error Messages

**"Invalid tool input schema"**
- Cause: Using unsupported JSON Schema features (`oneOf`, `allOf`, `anyOf` at top level)
- Solution: Simplify schema structure

**"model_context_window_exceeded"**
- Cause: Total tokens exceed model's context window
- Solution: Reduce conversation history or use 1M context beta for Sonnet 4.5

## Rate Limits

### How Rate Limits Work

Anthropic uses the **token bucket algorithm**:
- Capacity continuously replenishes up to your maximum limit
- No fixed interval resets
- More flexible than traditional rate limiting

### Rate Limit Dimensions

- **RPM:** Requests per minute
- **ITPM:** Input tokens per minute (only uncached tokens count)
- **OTPM:** Output tokens per minute

### Example Limits (Tier 1)

| Model | RPM | ITPM | OTPM |
|-------|-----|------|------|
| Claude Sonnet 4.x | 50 | 30,000 | 8,000 |
| Claude Haiku 4.5 | 50 | 50,000 | 10,000 |

### Tier Advancement

Automatic based on credit purchases:
- **Tier 1:** $5+ spend
- **Tier 2:** $50+ spend
- **Tier 3:** $200+ spend
- **Tier 4:** $400+ spend

Higher tiers provide significantly increased limits.

### Response Headers

```
anthropic-ratelimit-input-tokens-remaining: 45000
anthropic-ratelimit-input-tokens-reset: 2025-01-15T10:30:00Z
anthropic-ratelimit-requests-remaining: 48
anthropic-ratelimit-requests-reset: 2025-01-15T10:30:00Z
```

**Format:** RFC 3339 timestamps

### Cache-Aware ITPM (CRITICAL OPTIMIZATION)

**Key Insight:** Only **uncached** input tokens count toward ITPM limits.

With 80% cache hit rate and 2M ITPM limit:
- You can process 10M total input tokens
- 2M uncached (counted) + 8M cached (not counted)

**Benefits:**
- 10× throughput improvement possible
- Cached tokens billed at 10% of base rate
- Cache TTL: ~5 minutes (refreshed on use)
- 1-hour cache duration available in beta

### Handling Rate Limits

**Best Practice - Exponential Backoff:**
```csharp
int maxRetries = 3;
int baseDelay = 1000; // 1 second

for (int i = 0; i < maxRetries; i++)
{
    try
    {
        var response = await client.Messages.Create(params);
        return response;
    }
    catch (AnthropicRateLimitException ex)
    {
        if (i == maxRetries - 1) throw;

        int delay = baseDelay * (int)Math.Pow(2, i);
        await Task.Delay(delay);
    }
}
```

## Token Counting

### Importance

Token counting is essential for:
- Pricing calculation
- Context limit management
- Rate limit tracking

### Official Method

Use the SDK's `messages.countTokens` method for accurate counting:

```csharp
// Note: This is a future feature - check SDK docs for availability
var tokenCount = await client.Messages.CountTokens(new MessageCreateParams
{
    Model = "claude-sonnet-4-5-20250929",
    Messages = messages,
    MaxTokens = 1024
});
```

### Estimation

Rough estimate: 1 token ≈ 4 characters (English text)

**Warning:** This is very approximate. Always use official counting for accuracy.

### Usage Object

```json
{
  "input_tokens": 2095,              // Base input tokens
  "output_tokens": 503,              // Generated tokens
  "cache_creation_input_tokens": 0,  // Tokens used to create cache
  "cache_read_input_tokens": 0       // Tokens read from cache
}
```

**Total Input Calculation:**
```
Total Input = input_tokens + cache_creation_input_tokens + cache_read_input_tokens
```

**Billing:**
- Input tokens: Full price
- Cache creation: Full price
- Cache read: 10% of input price
- Output tokens: Separate pricing tier

## Context Windows

| Model | Standard Context | Extended Context (Beta) |
|-------|------------------|-------------------------|
| **Sonnet 4.5** | 200K tokens | 1M tokens* |
| **Haiku 4.5** | 200K tokens | N/A |
| **Opus 4.1** | 200K tokens | N/A |

*Requires beta header: `anthropic-beta: context-1m-2025-08-07`

### Long Context Pricing

Requests exceeding 200K tokens with the beta header:
- Incur additional costs
- Have separate rate limits
- Billed at different rate
